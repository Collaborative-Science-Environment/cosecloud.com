How it works

The instrument saves one still per interval into sessions/<name>/timelapse/, numbered in capture order, and records the interval and start time in experiment.json. This page reads those files, draws each frame at the output size with the overlay, and encodes the sequence with the browser's own H.264 encoder (WebCodecs), muxing into an MP4 that plays anywhere. On a browser without WebCodecs it falls back to recording the preview canvas, which gives a WebM file instead.

The elapsed time is the frame number times the interval, measured from the run start. The instrument keeps its capture schedule anchored to the start time rather than to the previous capture, so this stays accurate over a long run; a capture that failed (noted in events.csv) is skipped in the numbering, so after one the overlay runs early by one interval.

Frames are decoded one at a time, so a run of several thousand full-resolution stills is fine; the file size depends on the output size, frame rate and quality. A 24-hour run at 5-minute intervals is 289 frames, about 12 seconds of video at 24 fps.

Uses mp4-muxer (MIT). Nothing leaves your browser.
