Run setup

Prepare an instrument from your computer. Set the motor speeds, the run plan, the lighting presets, the camera and the display settings here, download scispinner-config.json, and put it on the instrument's USB drive. The settings are loaded the next time the Control Module starts. Everything runs in your browser; nothing is uploaded.

Lighting presets Lighting screen

Each preset is a whole-strip scene: the 90-pixel ring (pixels 1–90) and the 40-pixel halo (91–130), RGBW, 0–255 per channel, with one brightness for the scene. Later zones paint over earlier ones. The firmware keeps the strip under its 3000 mA budget by dimming an over-budget scene; the estimate below uses the controller's arithmetic.

  What the file contains
  
    The Control Module keeps its settings in a small JSON file, scispinner-config.json, on the module and on the USB drive. At start-up it reads the USB copy if there is one, and afterwards every change made on the screens is written to both. This page produces the same file from the same rules as the instrument's own screens:
    
  
      
    
    • Motors: frame_motor_speed, core_motor_speed (rpm; 0 or 0.050–5.000), frame_motor_direction_cw, core_motor_direction_cw, link_run. A power-cycled instrument never spins by itself; these set the dials for the next Run.
      • 
    
    • Run plan: exp_plan, the draft shown on the Experiment screen: name, duration, time-lapse interval, open-ended flag, and the lighting schedule steps (preset 0–4, value 1–99, unit minutes or hours).
      • 
    
    • Lighting: preset_1 to preset_4, each a list of LED commands (start_led, end_led, red, green, blue, white, brightness). The strip has 130 RGBW pixels: ring 1–90, halo 91–130.
      • 
    
    • Camera: camera with focus (af_mode, lens in dioptres), exposure (ae, ev), contrast, sharpness, zoom (0–0.8 crop), saturation, hflip, vflip, ir, res, fmt, fan.
      • 
    
    • Display: graph_windows (seconds shown on each Sensors graph) and theme.
      • 
  
    
  
    A file that is missing a key, or has an unusable value, falls back to the instrument's default for that key, so a partial or older file is safe to load. The page only writes keys it knows; anything else in a loaded file is passed through unchanged.
